# 拼多多视频（多多视频）接入方案与实现记录

> 版本：v1（2026-10 调研 + 落地）
> 结论先说：**能做，且不需要绕过任何风控**——拼多多有官方 PC 后台（`live.pinduoduo.com`），
> 达人身份用 App 扫码登录，发布页支持「立即 / 定时发布 + 标题 + 描述 + 话题 + 封面」。
> 唯一与传统四平台不同的地方是：**没有开放 API，只能页面自动化**，因此选择器要靠真机核对一次。

---

## 1. 通道调研（已核实）

### 1.1 通道对比

| 通道 | 能否发布 / 管理 | 结论 |
| --- | --- | --- |
| 开放平台 `open.pinduoduo.com` | ❌ 只有电商侧能力（商品 / 订单 / 物流 / 多多进宝），**没有视频发布接口** | 排除 |
| **官方 PC 后台 `live.pinduoduo.com`** | ✅ 商家 / 达人 / 机构三种身份登录，具备完整「发布视频 → 内容管理 → 数据中心 → 视频推广」 | **选它** |
| 机构后台 `mcn.pinduoduo.com` | ✅ 面向 MCN 的入驻与达人管理（仅企业主体） | 矩阵运营的官方通道，本期不做 |
| 手机 App / 群控 | ✅ 功能最全，但自动化只能靠模拟器，风控暴露面大 | 不采用 |

### 1.2 登录方式（三种身份，各不一样）

登录页明确给出身份选择：**我是商家 / 我是达人 / 我是机构**。

| 身份 | 入口 | 方式 | 本期 |
| --- | --- | --- | --- |
| **达人** | `/login/anchor` | App 扫码（`token_type=2`），二维码是 **data URL** | ✅ 做 |
| 商家 | `/login` | 账号密码 / 手机短信 | ❌ 不做（短信在无头模式下无法完成） |
| 机构 | `mcn.pinduoduo.com` | 企业主体资质 | ❌ 不做 |

> 实测：未登录访问发布页会被 302 到
> `/login?isNewCreatorFrom=…&referUrl=/n-creator/video/short-video`；点「我是达人」进入
> `/login/anchor`，页面上的二维码是 `<img class="anchor-login-section_qrCode__…">`，
> 内容是 `data:image/png;base64,…`（160×160），解码后指向
> `https://mobile.yangkeduo.com/down_scan.html?secret_key=…`（拼多多 App 扫码入口）。

### 1.4 内部接口（发布链路，签名由页面自己算）

```
POST /api/backbone/video/publish              视频发布（{feeds:[{goodsIdList, url, vid}], sourceSubType}）
POST /api/backbone/video/pictures/publish     图文发布
GET  /api/backbone/video/publish_qualification 发布资格校验（hasQualification + reason）
GET  /api/backbone/video/quality/check         视频质量预检
POST /mms/amco/prePublish/{add,query,delete,clear,sign}   草稿箱
GET  /api/backbone/video/{query,detail,delete,top,statistic/view,violation}
     /api/backbone/comment/{list,add,delete,like,unlike}
     /api/backbone/ddjb/{bind,query_stat,query_goods_stat}  多多进宝挂品 / 佣金
     /api/backbone/exam/{check/participate,query/exam_question,submit/exam_answer}  匹配度测试
```

**所有 `/api/backbone/*` 请求都带平台自己算的签名**（页面里用
`AntiContent.setScene().setSignatureHost(location.hostname).setTag("backbone-video-sign").init()`），
上传另外还要带 `anti-content` 头。这就是"不复刻签名、走页面自动化"的直接原因。

### 1.5 平台侧约束（都取自其发布页前端产物，不是猜的）

| 约束 | 值 |
| --- | --- |
| **视频没有标题字段** | 发布载荷里 `title` 只出现在 `feedType === IMAGE`（图文）那一支；视频那一支只有 `desc / cover / vid / scheduleTime / goodsIdList / cutStartTime…`。发布页上 placeholder=「添加标题」的输入框，渲染条件同样是 `feedType === IMAGE` |
| 标题（**只有图文有**） | ≤ 40 字，**不允许**出现 `#` 话题 |
| 描述（视频唯一的文案位） | ≤ 500 字；编辑器是**富文本 contenteditable**（SABO/ACE，CSS Module `text-edit_*`），不是 textarea |
| 话题 | 写在描述里（`#话题`），单个 ≤ 15 字，**最多 5 个**（「最多可以添加5个相关话题」，编辑器里 `limit:5`） |
| 封面 | **必须存在**（「请添加封面」/「请将全部视频添加封面」），规格 **3:4 竖版、≥720P、≤5MB**（「需上传封面比例为3:4且分辨率大于720P；文件大小不超过5M」） |
| 发布按钮 | **每张视频卡片上的「发布」**（`video-list_singlePublish`），点完变「发布中」→「已发布」 |
| 成功信号 | **平台没有"发布成功"这句文案**，成功只是把卡片改状态 + 打个内部事件；唯一一手证据是 `POST /api/backbone/video/publish` 的回执 |
| 视频规格 | mp4 优先、1080P 及以上、帧率 ≥ 24、码率 ≥ 6Mbps、竖版更易获流量 |
| 发布方式 | 立即发布 / 定时发布 |
| 其他 | 草稿箱、「上次有 N 个视频上传成功但未发布，是否继续发布」提示、带货视频需先过「匹配度测试」 |

> 这张表里有一半是**推翻了初版方案**的：初版按"文案先写一版"的思路以为视频有标题框、
> 描述是 textarea、发布成功后页面会出现「发布成功」。真去读它的构建产物才发现三条都不对——
> 而这三条每一条都会让首次跑真实账号直接失败（或更糟：报假成功）。

### 1.6 真机核对结果（2026-10-08，用真实登录态逐条核对）

首次真实扫码登录**失败了**——扫码本身成功（cookie 落盘、`L_PASS_TYPE=2` 确认是达人身份），
但被登录态校验判成失效、账号没入库。用那个 cookie 逐条核对真实页面后，查出三处问题：

| # | 问题 | 真实情况 | 后果 |
| --- | --- | --- | --- |
| 1 | 发布页地址错 | `/n-creator/video/short-video` 只是**活动/任务落地页**（页面上一个输入框都没有，文案是"第1步 点击底部'发布视频'"）；真正的上传页是 **`/n-creator/video/home`**（点落地页的「立即发布短视频」会跳到这里） | 校验永远看不到上传入口 → 判失效 |
| 2 | 文件输入框是**隐藏**的 | 上传页上两个 input 都是 `visible=False`（`.mp4…` 与 `.jpg…`），拖拽区用「添加视频」按钮代替 | 我的查找函数要求"可见" → 永远找不到 |
| 3 | `video-list_success` 不是"已发布" | 它是**「视频上传成功」**的标签，上传完就在；`video-list_mask` 在 `publishing \|\| published` 时都会盖 | 拿它们当成功判据 = **上传完就报假成功** |

同时确认了初版三条修正（都是对的）：**没有标题输入框**（真机上 `input[placeholder*="标题"]` 命中 0 个）、
描述是 `text-edit_saboIpt__*` 里的 contenteditable、发布按钮在 `video-list_singlePublish__*` 卡片里
（页脚另有一个全局「一键发布」，确认弹窗选择器必须限定在 modal 内，否则会点到全局按钮）。

其他真机细节：
* 发布设置块是 `PublishTimeSetting_publishTime__*`，里面除了两个 radio，点「定时发布」后才出现
  一个 `placeholder="选择日期"`、值形如 `2026-10-08 16:42:40`（**带秒**）的输入框；
  同一页上还有个 `placeholder="请选择"` 的**商品选择器**，常驻可见——候选里放它会点错控件。
* 上传成功与否看 `video-list_uploadPercent__*` 的文案（完成时是「视频上传成功」）；
  视频卡片容器是 `video-list_itemWrap__*`。
* 验证用的小视频有下限：1 秒 240×426 的文件平台直接丢弃，5 秒 720×1280 才正常出卡片。
  （诊断过程中上传的测试视频**没有在账号里留下残留**：草稿接口 `prePublish/query` 返回 `total: 0`。）

修复后复验（同样用真实 cookie，不发布任何内容）：
`cookie_auth` 返回 **True**；`tools/verify_pdd_publish_page.py` 报告
`file_input → input[type="file"][accept*=".mp4"]`（命中，隐藏）、
`upload_button → button:has-text("添加视频")`（可见）、`title_input → 0 个`。

### 1.7 首次真实发布的两次失败（2026-10-08）与修复

失败现象：两次任务都走到「已点击发布，等待平台回执」，然后 60 秒超时，报
"点了发布但等不到任何回执（接口没响、卡片状态没变、也没有错误提示）"，平台上什么都没有。

**真正原因：内容声明没选。** 拼多多的「内容声明」是**必选项**（发布页上带红星），
`anchorDeclarationType` 为空时点「发布」**只弹一句警告、连请求都不发**：

```
TST_notice_5-180-0 TST_noticeWarn_5-180-0 → 「请选择内容声明」
```

而**我看不到这句警告**——提示层扫描只认 `toast/message/alert/tip`，
平台自己的类名是 `TST_notice*` / `TST_outerWrapper*`。于是"平台明确说了原因"变成了
"结论未知"，日志里完全指不到点上。这暴露了两件事：

1. 提示层扫描要覆盖平台自己的组件类名（`TST_notice`）；
2. **必选项要在提交前就设好**，不能等平台拒绝。

修复（都已在真实账号上验证）：

| 改动 | 说明 |
| --- | --- |
| `_visible_toast_text` 补 `TST_notice` / `TST_outerWrapper` | 平台的中文提示终于能读到了 |
| 新增 `_set_content_declaration()` | 提交前选内容声明；选项来自发布页初始化接口的 `anchorDeclarationList`：内容无需标注(11) / 含AI生成内容(1) / 含虚构演绎内容(5) / 内容含营销信息(7) / 内容为转载(3) / 个人观点，仅供参考(8)，默认取 `conf.PDD_CONTENT_DECLARATION`＝「内容无需标注」 |
| 下拉框改用 `data-testid="beast-core-select"` | 平台自己打的稳定 hook，比 class 稳 |
| 选项选择器限定在 `[class*="ST_dropdown"]` 里 | `ContentDeclaration_title__*` 这组类名**同时被"?"图标的说明浮层复用**，全局找会点到说明文字上 |
| **回读选中值读 `input.value`，不是 `innerText`** | 这个 Select 的选中值渲染在 `<input value="…">` 里，`innerText` **不包含 input 的 value**——第一版验证脚本因此把"已经选上了"误判成"没选上"（截图里明明显示着「内容无需标注」） |

真机验证（不发布任何内容）：上传视频 → 点「发布」→ 读到 `请选择内容声明`（证明提示层修好了）
→ 调 `_set_content_declaration()` → 返回 `True`、回读值 `'内容无需标注'`。

离线自测同步补了回归守卫：假页面按真实结构加了内容声明下拉（含"值写在 input.value 里"这个坑），
**没选声明时也照真机那样只弹 `TST_notice` 警告、不发请求**；场景①断言声明确实选上了，
新增场景⑨断言"没有声明控件时"驱动要**点名内容声明**且平台 0 次提交。

### 1.8 第三轮真机失败：封面 + 协议弹窗 + 冷静期（2026-10-08 傍晚）

上一轮修完内容声明后，真机（账号 `麻辣腐竹`，id=7）再发两次**仍然失败**，报的还是
"点了发布没回执"。用同一个账号逐条核对，查出三件事：

| # | 问题 | 真实情况 | 后果 |
| --- | --- | --- | --- |
| 1 | **封面是硬前提**，我却"等平台拒绝再补" | 没有封面时点「发布」，平台只弹一句「请添加封面」（`TST_notice`），**什么都不做** | 发不出去 |
| 2 | **冷静期(6s) > 提示存活时间(约2s)** | 平台的警告是 `warn(msg, 2000)`，只显示 2 秒；`_submit` 点完先睡 6 秒再检查，**永远读不到那句提示** | 明明平台说了原因，日志却只有"没回执" |
| 3 | **协议弹窗没被处理** | 点「发布」有时会弹「我已阅读并同意《拼多多短视频管理规范》」+「同意并发布」/「不同意」，**不勾协议不点确认就不会发请求**；而我的兜底找的是页脚那个全局「一键发布」，永远匹配不到 | 弹窗一直开着，等到超时 |

修复：

* **封面改为提交前无条件设置**（`_set_cover_if_needed` 重写）。真机核对出的完整链路：
  点卡片「编辑封面」→ 弹「封面选择」窗（默认停在 **「视频截取」** 页签）→
  **必须点「本地上传」** 页签，图片文件输入框（`accept=".jpg,.jpeg,.png"`，隐藏）才出现 →
  塞图 → 点「确定」→ 卡片封面区出现 `<img>` = 成功。
  没有现成封面图时用 `_auto_cover_frame` 抽视频首帧生成一张 3:4 合规图。
* **冷静期 6 秒 → 1 秒**，并把提示层基线也带上（只认"点发布之后新出现的提示"，
  避免重试时把上一次的旧提示当成这次的拒稿）。
* **协议弹窗**：用平台自己的 `data-testid="beast-core-modal-ok-button"` 找确认按钮，
  点之前先勾「我已阅读并同意」（勾选框本体是 `opacity:0` 的隐藏 input，点它旁边的文案）。

**证据（这批修复是真的通了）**：最后一次真机验证时，内容声明 + 封面都设好之后点「发布」，
平台**直接受理并生成了作品**（作品管理里出现 17:55:41 那条，`上传成功` 提示弹出、
本次没有弹协议窗）。那条是我用 ffmpeg 生成的测试视频，平台给的结论是
**「生成失败：视频无音频，请更换视频」**——说明**没有音轨的视频平台不收**（真实素材带 BGM 不受影响）。
测试作品已从作品管理里删除，账号回到原本的 2 条作品。

> 顺带确认：平台上"上传成功但未发布"的视频会进**草稿**（发布页只显示一句
> 「上次有N个视频上传成功但未发布，是否继续发布」）。驱动一律点「取消」，**不会**把草稿替用户发出去。

### 1.9 第四轮：视频发上去了，记录却写"失败"（2026-10-08 晚）

内容声明、封面、协议弹窗都修好之后，用户再发两条——平台上**都成功了**
（作品管理里 18:19:35 / 18:20:05 两条，标题、AI 文案、话题都在），
但**发布记录写的是"失败：平台拒绝了这次发布：1000000"**。

原因：拼多多的响应信封是 `{success, errorCode, errorMsg, result}`，
**成功时 `errorCode` 也是非空的**——实测发布页初始化接口就是
`{"success": True, "errorCode": 1000000, "errorMsg": None, ...}`。
而 `_publish_response_error` 当时写的是"看到 errorCode 就当失败"，
于是把成功回执读成了拒绝，把两次**已经发布成功**的任务记成了失败。

修复：

* 判读顺序改成：`success === False` → 失败；错误文案字段非空 → 失败（把平台原话带出去）；
  `errorCode` 非空**且不在成功码白名单**（`PDD_RESPONSE_OK_CODES = {"0", "1000000"}`）
  且 `success` 不是明确的 true → 失败；其余一律成功。
* 成功回执也把响应体压成一行记进日志（`_brief_json`），下次排障一眼就能看到平台回了什么。
* 协议勾选框的点击加了 JS 兜底：真机上出现过"文案点不动（3 秒超时）"，
  而勾选框本体是 `opacity:0` 的隐藏 input，用 JS 点更稳。
* **离线自测的假服务器改成回真实信封**（成功：`success:true + errorCode:1000000`；
  拒稿：`success:false + errorCode:400010 + errorMsg`）——否则这条 bug 在回归时抓不回来。
  单测同步换成真实信封（`PddResponseVerdictTests`）。

> 这两条作品的发布记录仍是"失败"（记录是日志，不回改历史）。**素材本身已经发过了，
> 不要再用同一条素材往拼多多重发**，否则平台上会出现第二条重复内容。

### 1.10 第五轮：批量发布时有 3 条卡在上传（2026-10-09）

用户发了一批 22 条，**19 条成功、3 条卡住被手动中断**（#206 卡 3 分钟、#211 卡 8.7 分钟、#219 卡 3 分钟）。
排查结果：

* **素材本身没问题**：卡住那两条 4.7MB / 4.2MB、时长 10.5s / 24.7s、都有音轨，
  和"成功且只用 13 秒传完"的那些没有区别；
* **平台侧根本没收到**：草稿箱 `prePublish/query` 是空的（不是"传完了没发"）；
* **日志显示卡在同一个位置**：选完文件之后 `_wait_upload_finished` 再没有任何输出——
  平台的视频卡片一直没建出来；
* 出现位置没有规律（第 7 / 12 / 20 条），**像是平台侧上传偶发不响应**（约 15% 的概率），
  而不是文件太大或限流。

真正的问题是**工具的反应**：卡住了只是安静地等满 10 分钟（`PDD_UPLOAD_TIMEOUT_SECONDS=600`），
界面上只有一个转圈，用户只能手动中断——三条都是这么被中断的。

修复：

| 改动 | 说明 |
| --- | --- |
| **卡住检测** | `_wait_upload_once` 每 3 秒看一次"上传进度文案"（`video-list_uploadPercent__*` / 卡片区域）；**45 秒没有任何变化且卡片没出来**就判定卡住 |
| **自动重传一次** | 判定卡住 → `page.reload()` + 重新进上传页 + 重新选文件（卡死的上传器/请求靠重载清掉）→ `conf.PDD_UPLOAD_RETRIES`（默认 1） |
| **快速失败并说清楚** | 重传后仍卡住 → 抛「平台侧上传没完成：文件已经选中，但 N 秒内平台始终没有把视频收下（已自动重传 X 次）。这不是本地文件的问题，多半是平台那一次上传/转码没有响应——过一会儿重发即可」 |
| **过程可见** | 每 30 秒打一条「还在等平台接收/转码… 已等 N 秒（进度：…）」，不再是纯转圈 |
| **上传阶段的平台报错也读了** | `UPLOAD_ERROR_HINTS`：超出最大时长 / 暂不支持上传 / 上传失败 / 网络错误 / 获取 endpoint 失败 … 出现就立刻失败并翻译成人话 |
| 阈值可调 | `SAU_PDD_UPLOAD_STALL=120`、`SAU_PDD_UPLOAD_RETRIES=1` |

离线自测新增场景⑩：假页面**第一次上传永远不完成**（真机实测的现象），断言驱动会
"判定卡住 → 重新加载并重传 → 成功"，且最终只提交一次；场景⑤改成断言"**不再**安静地等 10 分钟，
而是快速失败并说明是平台侧没接收"。

### 1.11 账号数据（粉丝/作品）改用网页端抓取（2026-10-09）

用户提的：「拼多多视频的详情粉丝数据接口拿不到，不应该也从网页端去获取一下吗，快手就是这么做的」——
说得对。拼多多**没有可直连的数据接口**（后台所有 `/api/backbone/*`、`/sprite/obs/*` 都带页面现算的签名），
但这不等于拿不到数据：照搬快手那条已验证的路子就行——

    **开浏览器进创作者后台，让页面自己去发那些请求，我们只把响应收下来解析。**

真机核对（2026-10-09，账号 `麻辣腐竹`）确认了数据来源：

| 接口 | 页面 | 拿到什么 |
| --- | --- | --- |
| `/sprite/obs/anchor/info` | 发布页 `n-creator/video/home` | 昵称、头像、`anchorUid`、**粉丝数**（`fansNumDataTip`，是字符串 `"1"`）、直播间 ID |
| `/api/backbone/anchor/query` | 发布页 | 昵称/头像/`anchorUid`/`roomId`（与上面互为兜底） |
| `/api/backbone/video/statistic/view` | 数据总览 `video-all-data` | 账号级总览（视频发布量/播放量/点赞数/分享量/评论数/粉丝净增值）+ 每指标的**7 天、30 天增量**与**近 31 天逐日序列** |
| `/api/backbone/video/query` | 作品管理 `video-manage` | 作品列表（`feedId`/描述/封面/播放 `vv`/点赞/评论/分享/发布时间）+ 总数 |

实现：`myUtils/account_stats/pdd.py`，注册进 `ADAPTERS[5]`。于是既有的三个入口自动都有了——
「账号管理 → 详情 → 同步」「定时续期顺带同步」「新账号扫码登录后自动同步」。

几个如实处理的点：

* 粉丝数平台给的是**字符串**（`"1"`、甚至 `"1粉丝"`）→ 转成 int；
* 作品级**分享数**经常是 `null` → **不写进这一行**（显示"平台没给"），而不是显示 0；
* 作品标题平台视频为空的用描述首行代替；
* 成功信封里 `errorCode` 也是非空的（1000000），判读只看 `success`/`errorMsg`。

真机结果：`sync_account` 返回「数据已同步（粉丝 1、作品 5）」、耗时 18 秒，缓存写入成功；
单测用**真机抓到的响应做夹具**（`tests/test_pdd_stats.py`，12 条）。

### 1.12 头像也同步到本地（2026-10-09）

用户诉求：「同步过账号详情的账号把头像也同步到本地来，不然本地的几个头像还是显示的文字」。

问题是：各平台的同步结果里本来就带远程头像 URL（`stats.account.avatar`），但账号管理列表
一直用的是**第三方文字头像服务**（`ui-avatars.com`）——离线或不联网时就是一片"文字头像"。
而直接引平台 CDN 地址也不稳：热链不一定放行、部分平台的 URL 带时效，表现是随机裂图。

做法：**同步时把头像下载到本地**，列表改读本地路由。

* `myUtils/account_stats/avatar.py`：`store_avatar(account_id, url)` → 落到
  `avatars/<账号id>.<扩展名>`（按 Content-Type 定扩展名、先写 `.part` 再原子替换、
  体积上限 2MB）。旁边记一个 `<账号id>.url` 记录来源 URL：**URL 没变就不重复下载**
  （同步有三个入口：详情页 / 定时续期 / 新账号登录，每次重下纯属浪费）。
* 落地挂在 `sync_account()` 里、**成功抓到数据之后**，而且失败只记日志：
  没有头像只是列表少张图，粉丝/作品那些主数据不该被它拖累（有单测钉住这条）。
* 后端新增 `GET /account-stats/avatar/<账号id>`（在账号数据那个蓝图上）：
  有图就发图并带 5 分钟缓存头，没有就 404。
* 前端 `AccountManagement.vue`：`el-avatar` 的 `:src` 改成优先本地路由
  （`<img>` 带不了请求头，token 走查询串——和扫码登录那两个 SSE 同一个办法），
  加载失败就回退成原来的文字头像；账号列表每次刷新都会清一次"失败缓存"，
  所以**先同步、后刷新**就能看到头像从文字变成图。

真机结果（2026-10-09）：账号 7（拼多多）同步返回「数据已同步（粉丝 1、作品 5、头像已更新）」，
`avatars/7.jpg` 4196 字节；顺手把小红书(1)、快手(3)、抖音(4) 也同步了一遍，头像都落地了
（视频号那个账号本身登录态已失效，与本次改动无关）。

### 2.0 离线自测（没有账号也能验的那一半）

选择器已经用真实登录态核对过（见 1.6），但流程逻辑仍然由这一层守着：`tools/verify_pdd_publish_flow_offline.py`
起一个本地 HTTP 服务，用拼多多发布页的**已知文案**搭一张假页面，再让真实的 `PddVideo`
带着假 cookie 去跑九个场景——立即发布 / 定时发布 / 接口回执 / 登录失效 / 上传卡住 /
**定时控件缺失时不许降级**（这一条验的是「服务端 0 次提交」，即没有偷偷改成立即发布）/
**缺封面时自动补一张 3:4 封面并重试一次** / **走发布中心自己的代码路径发一条**
（`_build_tasks` → `_invoke_uploader` → 真实驱动：验的是接线，不只是驱动）。

> 假页面本身也照平台真实结构搭：描述是 `text-edit_saboIpt__*` 的 contenteditable、
> 发布按钮在 `video-list_singlePublish__*` 卡片里、成功后平台给卡片盖 `video-list_mask__*`、
> **没有标题输入框**、发布走 `POST /api/backbone/video/publish`。它验的是真实结构，
> 不是"我想象中的页面"。

```bash
.venv/bin/python tools/verify_pdd_publish_flow_offline.py            # 无头
.venv/bin/python tools/verify_pdd_publish_flow_offline.py --headed   # 看着它操作
```

它第一次跑就抓出两个**会在真平台上出事**的 bug，两个都已经修掉并钉进单测
（`tests/test_pdd_publish.py` 的 `PddPageInteractionTests`）：

| bug | 症状 | 修法 |
| --- | --- | --- |
| 用 `.first` 取元素 | `.first` 是"DOM 顺序第一个"，不是"第一个可见的"。页面上隐藏的同名按钮（比如弹窗里的「仍要发布」）排在真按钮前面时，**永远命中不到可见的那个**——发布停在"找不到发布按钮"，而页面上明明有 | `_first_visible` 逐个往后找可见的元素（有界扫描） |
| 用 `page.content()` 判文本 | 源码里包含打包进来的文案常量（「发布成功」就在拼多多自己的 JS 里），按源码匹配**每次都会匹配上** → 每次都报假成功，发布记录写"成功"而平台上什么都没有 | 一律用 `innerText`（`_visible_text`）判可见文本；拒稿文案只认 toast 里的或"点发布之后新出现"的 |

这两个都属于"真平台上不一定立刻暴露、但一旦暴露就非常难查"的类型——这正是离线自测的价值。

### 2.1 发布链路与每一步的判据

1. **打开发布页** `https://live.pinduoduo.com/n-creator/video/short-video`；
   被跳到 `/login` → 判为登录态失效（老版路由 `/creator/short-video` 会再试一次）。
2. **关掉挡路弹窗**：「上次有 N 个视频上传成功但未发布」一律点「取消」（不替用户发出残留半成品）。
3. **上传**：优先 `input[type=file][accept*=".mp4"]`；找不到就点「添加视频」走系统文件选择器。
4. **等上传完成**：判据是**发布表单可编辑**（标题输入框出现）且页面上没有「上传中」文案，
   超时 10 分钟——不用固定 `sleep`。
5. **填标题/描述**：标题去 `#` 并截断到 40 字；描述 = 正文 + `#话题`（>15 字的话题丢弃），截断到 500 字。
6. **封面**：用调用方给的封面；没有就用 ffmpeg 抽**视频首帧**生成一张
   （`pdd_debug/covers/<素材名>.jpg`，并发安全：临时目录 + 原子替换）。失败只告警，由页面兜底报错。
7. **定时**（仅在定时发布时）：点「定时发布」→ 填 `YYYY-MM-DD HH:mm`。
   **失败直接报错，绝不降级为立即发布**（那会把"定时"变成"现在发"，是最坏的结果）。
8. **提交**：点卡片上的「发布」，然后按信任度依次看
   ①`POST /api/backbone/video/publish` 的**接口回执**（唯一一手证据）
   → ②卡片进入已发布状态（`video-list_success` / mask）
   → ③toast 里的拒稿原因（翻成人话：缺封面 / 描述超长 / 话题超限 …）。
   **缺封面是唯一值得补救的一种拒绝**：驱动会自动抽视频首帧生成一张 3:4 合规封面，
   再重试一次（本地校验失败时平台什么都没收到，重试没有重复发布风险）。

### 2.2 明确**没做**的事

- **不挂商品**：达人挂品要先通过拼多多的「匹配度测试」，本期只发内容视频。
- **不做商家 / 机构身份**：登录方式不同，且商家要短信。
- ~~不做账号数据同步~~ → **已做**（见 1.11）：粉丝、账号级总览、7/30 天口径、逐日序列、作品列表都有。
- **不做图文 / 短剧**：后台有对应接口（`video/pictures/publish`、短剧管理），留作后续。

## 4. 风险与注意事项

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 页面改版 | 选择器是最容易过期的东西 | 选择器集中在一处；失败自动落现场；`tools/verify_pdd_publish_page.py` 一键复检 |
| 风控 / 账号安全 | 平台对"重复视频、低质量视频"有明确限制，2025 年起主推 V 计划与原创认证 | 只用于自有账号的合规发布；保留人工确认闸门；不要做搬运矩阵 |
| 定时控件不确定 | 定时用的日期时间选择器无法离线确认 | 失败即报错并留现场，不静默降级 |
| 封面 | 平台强制要求 | 自动用视频首帧生成；失败时给可操作的报错 |
| 会话保活 | 登录态是服务端会话，本地 `expires` 不作数 | 纳入既有的「定时续期」（0/7/14/20 点），续期时回写 cookie |

> ⚠️ 合规提醒：这套工具只做"把人工发布流程自动化"，不包含、也不应该包含任何
> 绕过平台风控、伪造内容或批量搬运的能力。搬运算号在多多视频明确拿不到补贴，且会被处罚。
